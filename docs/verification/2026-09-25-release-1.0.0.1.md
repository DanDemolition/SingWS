# SingWS 1.0.0.1 release verification

Built from d68876f plus the synchronized 1.0.0.1 version bump. Release-only changes update the download page/manifest and one stale test assertion to inspect the shared KaraFun result resolver.

## Changes

- Scanned-tail completion honors the configured hold and requires confirmed lyric completion.
- KaraFun activation resolves the matched result again after screen movement; completed handoffs can raise the existing audience renderer.
- Network Settings includes an experimental windowed transparency handoff. It remains disabled by default. It verifies renderer placement before making SingWS transparent and click-through, and restores saved native mouse behavior and opacity afterward.

## Build

Host: Apple Silicon, with Intel Python/PyInstaller under Rosetta. Native playback libraries were reused from the architecture-specific inputs used for 1.0.0.

```sh
./.venv/bin/python tools/release_version.py --set 1.0.0.1
./build_singws_mac_arm64.sh
SINGWS_BUILD_PYTHON="$PWD/.venv-build-intel-rosetta/bin/python" \
SINGWS_NATIVE_PYTHON="$PWD/.venv/bin/python" \
SINGWS_MPV_FRAMEWORKS="$PWD/native_dual_view/Frameworks-intel-release" \
SINGWS_MPV_BRIDGE="$PWD/native/mpv_bridge/libsingws_mpv_bridge-intel.dylib" \
SINGWS_PYINSTALLER_WORKPATH=build-release-1.0.0.1-intel ./build_singws_mac_intel.sh
```

Both app builds and their architecture, minimum-OS, media-core loading, and ad-hoc signing checks passed. Both scripts then encountered the existing sandbox disk-image packaging failure. Packaging succeeded outside the sandbox using clean signed copies staged at `/tmp/singws-1.0.0.1-arm64/dist/SingWS.app` and `/tmp/singws-1.0.0.1-intel/dist/SingWS.app`:

```sh
SINGWS_DMG_APP_ROOT=/tmp/singws-1.0.0.1-arm64 ./.venv/bin/python -m dmgbuild \
  -s dmg_settings.py SingWS-1.0.0.1 SingWS-1.0.0.1-arm64-installer.dmg
SINGWS_DMG_APP_ROOT=/tmp/singws-1.0.0.1-intel ./.venv/bin/python -m dmgbuild \
  -s dmg_settings.py SingWS-1.0.0.1 SingWS-1.0.0.1-x86_64-installer.dmg
hdiutil verify SingWS-1.0.0.1-arm64-installer.dmg
hdiutil verify SingWS-1.0.0.1-x86_64-installer.dmg
```

Apple Silicon architecture verification: 419 Mach-O files; minimum OS <= 12.3. Intel: 432 Mach-O files; minimum OS <= 12.0. Both staged signatures passed `codesign --verify --deep --strict`, and both DMGs passed `hdiutil verify`. Frozen-code markers for the new tail hold, KaraFun resolver, and experimental reveal were found in both executables.

## Tests

The complete general/GUI selection produced 1,076 passes, 49 passing subtests, and one stale source-inspection assertion. After updating that assertion to follow the shared resolver, its complete module and release-tool tests passed: 163 tests and 8 subtests. All 1,077 selected general tests are covered by the successful initial tests and affected-module rerun. Separately, the four native modules passed all 92 tests.

The GUI run used `.venv-test-arm64-fresh/bin/python`, `QT_QPA_PLATFORM=offscreen`, and platform plugins copied without extended attributes to `/tmp/singws-release-1.0.0.1-qt-platforms` with hidden flags cleared, as required for the previous release. Every automated run used a fresh scratch `SINGWS_HOME`; live log counts were unchanged before manual launch checks.

```sh

QT_QPA_PLATFORM_PLUGIN_PATH=/tmp/singws-release-1.0.0.1-qt-platforms \
SINGWS_SKIP_GSTREAMER_INIT_FOR_TESTS=1 ./.venv-test-arm64-fresh/bin/python - <<'PY'

                                     if p.name not in excluded]))
PY
SINGWS_HOME=$(mktemp -d) QT_QPA_PLATFORM=offscreen \
```

## Installed launch checks and limits

No new SingWS native crash reports were found. Restored the validated Apple Silicon 1.0.0.1 app as this Mac's installed app and left it closed.

These are launch/layout checks, not a full playback rehearsal. Intel was launched under Rosetta, not on physical Intel hardware. The experimental option remains off by default and should be rehearsed before live use.
