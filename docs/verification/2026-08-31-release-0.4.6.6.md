# SingWS 0.4.6.6 release verification

The operator requested build and publication after testing the normal app.
Version 0.4.6.6 is a patch increment from 0.4.6.5, with an Intel/macOS 12+
installer matching the platform offered by the previous release.

## Scope and source

The release includes the accumulated waveform, ready-singer audience rotation,
host focus/ticker, KaraFun lifecycle/completion, background crossfade, history
sync and exception-reporting fixes. Their individual verification notes remain
in this directory. Coordinated server statistics fixes were deployed earlier
on August 31; no new server deploy or history reset is part of this release.

Before the version bump, all 24 production source hashes matched the installed
candidate `2af5d6fe2909af944ea820172d981858285da621e025ff31f4640d261462edfe`.
The only production difference from that candidate is APP_VERSION. Both specs'
bundle versions are updated to match. The release snapshot is separate from
the regular build/dist directories:
`/private/tmp/singws-release-0.4.6.6/`.

## Automated checks

- 991 desktop tests plus 39 subtests pass using the working Qt environment.
- 86 native-engine tests pass using the packaged-build Python environment.
- 282 focused GUI and safety tests pass independently.
- All five server history/request suites pass in disposable server copies.
- All 16 release-tool tests pass after the version bump.

The first `tools/run_tests.sh` attempt did **not** pass: its old `.venv-test`
cannot create QApplication, and it aborts when a newer GUI suite reaches that
path. The faulting stack is Qt platform integration in the test runtime, not
the installed app. No production code or assertions were relaxed. The complete
suite was rerun with working Qt, and the four tests requiring the native
environment were run separately as documented in AGENTS.md:

```sh
SINGWS_HOME=$(mktemp -d) QT_QPA_PLATFORM=offscreen \
SINGWS_SKIP_GSTREAMER_INIT_FOR_TESTS=1 \
PYTHONPATH="$PWD/qtvenv/lib/python3.14/site-packages:$PWD/.venv-test/lib/python3.14/site-packages" \
./qtvenv/bin/python -m pytest -q --ignore=vendor --ignore=test_bass_init_once.py \
  --ignore=test_karaoke_engine_selection.py --ignore=test_libmpv_background_engine.py \
  --ignore=test_mac_keep_awake.py --ignore=test_phrase_detect.py

SINGWS_HOME=$(mktemp -d) QT_QPA_PLATFORM=offscreen \
./.venv-universal/bin/python -m unittest test_karaoke_engine_selection \
  test_libmpv_background_engine test_mac_keep_awake test_phrase_detect

python3 ../SingWS-Server/tools/run_history_regressions.py
```

The standalone `test_bass_init_once.py` diagnostic is not a collected test and
is excluded by the existing release runner. No automated tests use the normal
show profile. The running normal app continues its ordinary network logging;
that log growth is distinct from scratch-profile test output.

native mpv frameworks. The normal app and profile are backed up in the private

## Limits disclosed before publication

The installed candidate's audience ticker, host stacking and a normal mouse
click on the bottom Settings button were visually checked. The operator also
reported the other fixes working during their tests. These facts do not prove
all physical playback combinations work.

A full KaraFun song ending followed by the next local video, together with an
external audience display, has not been rehearsed. Status probes can still
take 5–10 seconds. The earlier idle session also logged intermittent web-preview
connection timeouts while the request relay remained connected. Do not claim
those network issues or full show-hardware validation are solved by this
release. The release notes explicitly state the playback/hardware limits and
the possibility that macOS requests renewed Automation/Accessibility permission.
