# SingWS 1.0.0 release verification

Version: 1.0.0. Built from e33f4b4 plus the synchronized version bump. Release-only changes update the download page/manifest and two stale regression expectations: the existing 1000 ms playback backdrop timer and the corrected `ui_now_singing_update` diagnostic name.

## Build

Host: Apple Silicon (arm64); older repository machine notes describe a previous Intel host.

```sh
./.venv/bin/python tools/release_version.py --set 1.0.0
./build_singws_mac_arm64.sh
SINGWS_BUILD_PYTHON="$PWD/.venv-build-intel-rosetta/bin/python" \
SINGWS_NATIVE_PYTHON="$PWD/.venv/bin/python" \
SINGWS_MPV_FRAMEWORKS="$PWD/native_dual_view/Frameworks-intel-release" \
SINGWS_MPV_BRIDGE="$PWD/native/mpv_bridge/libsingws_mpv_bridge-intel.dylib" \
SINGWS_PYINSTALLER_WORKPATH=build-release-1.0-intel ./build_singws_mac_intel.sh
```

Both apps built. Disk-image creation required running dmgbuild outside the sandbox, using clean copies staged under `/tmp/singws-1.0-arm64/dist` and `/tmp/singws-1.0-intel/dist`. Intel packaging succeeded on retry after a temporary disk-image resource error. Staged apps were signed with the repository's existing ad-hoc signing/entitlements procedure.

- Apple Silicon: 419 Mach-O files passed architecture verification; deployment targets <= macOS 12.3.
- Intel: 432 Mach-O files passed architecture verification; deployment targets <= macOS 12.0.
- Both bundled media cores loaded successfully.
- Both staged signatures passed `codesign --verify --deep --strict`.
- Both installers passed `hdiutil verify`.

## Tests

1,061 GUI/general tests and 39 subtests passed in the fresh Qt environment. The four native modules (`test_phrase_detect`, `test_libmpv_background_engine`, `test_mac_keep_awake`, `test_karaoke_engine_selection`) passed separately: 92 tests in `.venv/bin/python`. Release-tool tests also passed (16 tests).

The fresh Qt environment lacks native dependencies, so those four modules must be excluded from its explicitly supplied file list rather than relying on pytest `--ignore` to override explicit paths. macOS hidden flags on platform plugin files caused Qt to skip them; copying the plugins without extended attributes to `/tmp/singws-qt-platforms`, clearing the hidden flags, and setting `QT_QPA_PLATFORM_PLUGIN_PATH` resolved that environment issue. No runtime plugin change was required.

Every automated run used a scratch `SINGWS_HOME`. The existing September 20 live log remained at 2,449 lines before manual app launches.

## Installed launch checks

Backed up `/Applications/SingWS.app` and `~/SingWS` to `local-installs/release-1.0.0/backup`. Installed and launched both variants sequentially under the normal app identity/profile. The operator window rendered and the normal server connection reached Connected. Intel ran under Rosetta. No new SingWS native crash report was found. Restored the Apple Silicon 1.0.0 build to `/Applications/SingWS.app` afterward.

These were launch/layout checks, not a full venue playback rehearsal. Physical Intel hardware and the venue's external displays/audio setup were not tested. Shawn's exact trailing-silence failure is not proven resolved; the reproduced metadata-failure path is fixed and three local Sound Choice tracks were verified during development.
